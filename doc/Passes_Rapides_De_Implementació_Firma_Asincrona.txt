Vamos a por el tema del API
===========================

* https://github.com/GovernIB/portafib/blob/portafib-3.0/doc/Manual_Integracio_API_Firma_Async_Simple_v2_0.odt : Este documento es de la API antigua pero contiene en la introducción el funcionamiento de la Firma Asíncrona (la que se envia a PortaFIB).
* https://github.com/GovernIB/portafib/blob/portafib-3.0/doc/Manual_de_Migraci%C3%B3_de_APIsIB_a_Api_Interna.odt: En este documento se explica la nueva API Swagger (Son las mismas clases que el API V2.0 pero con anotaciones Swagger/OpenAPI)
* https://se.caib.es/portafibapi/interna/index.html?urls.primaryName=Signature%20v1#/AsyncSignatureOnWeb%20v1: En está página podéis ver los métodos disponibles en el API de Firma Asíncrona. Incluso cuando tengáis el usuario aplicación para SE (Serveis Estables) podríais hacer pruebas de llamadas, aunque os aconsejo para las pruebas el punto siguiente.
* https://github.com/GovernIB/portafib/tree/portafib-3.0/api-interna-client-signature-v1-examples: Este es un miniproyecto en JAVA para probar la firma asíncrona (no incluye el CallBack, lo simula llamando varias veces a PortaFIB para averiguar el estado de la Petición de Firma). El test que debéis ejecutar es https://github.com/GovernIB/portafib/blob/portafib-3.0/api-interna-client-signature-v1-examples/src/main/java/es/caib/portafib/apiinterna/client/signature/v1/example/api/FirmaAsincWebV1ApiTest.java y la configuración se crea copiando el fichero https://github.com/GovernIB/portafib/blob/portafib-3.0/api-interna-client-signature-v1-examples/asyncsignatureonweb.properties.sample a asyncsignatureonweb.properties y actualizando los valores. Los campos importantes son: 

basePath=https://se.caib.es/portafibapi/interna
username=[ El que os pasen ]
password=[ El que os pasen ]
PROFILE=PADES  (pero que lo confirmen)
nifsDestinataris=123456789C  (DNI de la persona que debe firmar, en desarrollo la del desarrollador)

Para firmar a las Peticiones de Firma, creadas con esta API debéis acceder a https://se.caib.es/portafibback.




Para el CallBack, tenéis los siguientes recursos
================================================

* https://github.com/GovernIB/portafib/tree/portafib-3.0/ws/portafib_callback_server_rest: Ejemplo muy simple de implementación del Servio Rest de CallBack 
* https://github.com/GovernIB/enviafib/blob/enviafib-2.0/enviafib-api-interna/src/main/java/es/caib/enviafib/api/interna/all/portafibcallback/PortaFIBCallbackRestService.java: Ejemplo completo de implementación del Servio Rest de CallBack. Este ejemplo crea un thread para el procesamiento del aviso del Callback y responde rápidamente a PortaFIB de la recepción del evento. Hay que gestionar estados para la petición: enviada, procesando callback, error en callback y ejecutado callback. NUNCA se debe devolver un error a PORTAFIB !!!!!!
* https://github.com/GovernIB/portafib/blob/portafib-3.0/doc/Manual_Integracio_API_Firma_Async_Simple_v2_0.odt : A partir de la Fase 4.1 se documenta como implementar el CallBack
Una vez implementado el CallBack en vuestra aplicación, deberéis avisar a los Administradores de PortaFIB de la URL de callback (URL donde vais a escuchar los avisos del estado de la Petición) i 
* La forma de la URL deberia ser algo como: https://[HOST]:[PORT]/volantapi/interna/public/portafib/callback/v1
* La URL no debe ser autenticada, o sea que debe tener acceso publico.
